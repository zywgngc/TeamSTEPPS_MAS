# 核心设计与开发边界

## 研究问题

医学MAS需要保持任务目标、解释证据与不确定性、识别遗漏，并把有意义的问题交给可执行的后续工作。TeamSTEPPS提供团队协调原则：共享任务和职责、交叉监测、闭环沟通与相互帮助。本项目研究这些原则如何成为模型间的具体协议；增加轮数、合法JSON或全员同意不作为协作成功的定义。

## 当前实现

架构为MedAgents来源提示与原生对照，加本项目独立控制器。TeamSTEPPS条件复用作者专科招募与最终选项提示；专科工作、综合、复核与帮助流程由本项目实现。它不是完全不变的MedAgents流程加一层消息传输，也不依赖AutoGen承担科学贡献。

| TeamSTEPPS原则 | 当前实现 | 程序可确认的范围 |
|---|---|---|
| Brief与职责 | 原题、选项、证据和招募成员上的共享任务及分工 | 原始内容、分派与实际调用 |
| Situation monitoring | 临床cross-monitoring，检查任务、依据、方向和遗漏 | 原始状态、理由和后续控制流 |
| Check-back | 发送者核对自己被声明采用的主张及解释 | 原主张与读回的绑定、发送者实际回复 |
| Huddle | 针对开放问题决定行动、拒绝或保留 | 计划、具体任务、责任人与未决状态 |
| Task assistance | 接管单独调用，随后再执行并返回产出 | 接受、产出、送达与再处置的区别 |
| 通信效率 | 定向视图、可逆池化；全文广播和未池化条件 | 实际传输内容、调用与usage |

临床复核与原意核对使用同轮开始前的快照，不把本轮另一通道的标签当作判断输入。核对原意时恢复发送者自己的原工作请求与原回复。问题由原提出者复核，报告改写、引用命中或另一成员的同意不会自动关闭它。轮数上限后仍开放的问题保留至终答上下文。

来源ID明确关联随消息携带的原文；没有外部检索或新增检查工具。推断、计算、预测和已提供事实必须区分，不能以成员生成的内容冒充新增患者资料。

## 当前候选的限制

当前工作合同按`contribution/outside_role`分支，注册主张来自`claims`；采用与原意核对以该注册表为入口。状态之外的理由中仍可能包含实质工作，合法状态也可能与正文不一致。当前帮助触发依赖登记的问题标签，并不保证所有未完成职责或正文异议都被识别。完整输出字段合同主要由解码grammar承载，模型消息还没有覆盖所有字段定义。这些是需要修订的实现边界，不能将状态计数包装成语义评价。

## 后续设计方向，尚未实现

下一版优先恢复明确专科身份与当前可执行任务，将每份原始工作作为可追溯工件保存，不以成功登记`claims`决定它是否存在；综合者对影响决策的工作声明实际解释及条件，再由原发送者核对。团队状态检查需要读取实质理由与工作缺口，分别处理原意误读、临床依据问题和职责未完成。

进一步引入原生临床工作层与自定义通信控制层时，所有派生条件需共享同一基础工作接口；接口修复、额外知识、额外强模型和通信机制的作用应分别评价。检索、动态skill编辑、GEPA和自动prompt优化未实现为当前功能。

## 评价原则

主要关注任务保持、实质工作完成、关切依据与可操作性、接收解释保真、帮助是否真正执行、产出是否恰当进入后续决策。必须区分“没有适用机会”“未观察”“失败”和“完成”。独立内容评价与受控扰动可以评价语义质量，程序事件和模型自述本身不能提供医学金标准。准确率、token、调用和时延补充说明任务结果与代价。

当前仓库不提供已验证的临床收益主张或独立医学标注器。合成场景只验证控制流、权限、输入隔离与失败保留。
